# Hermes / AIAgent reference (authoritative — verify here, don't guess)

This project integrates with **Hermes's `AIAgent`** library (NousResearch/hermes-agent)
through one adapter, `cadre/model_client.py`. `AIAgent` is pre‑1.0 and
**volatile** (calendar‑versioned; `v2026.6.5` observed), so any claim about its
constructor params, toolset names, timeouts, or provider resolution **must be
checked against the sources below — never against model training data.** Guessing
here has already produced a real privilege bug (see "Verified facts" #1).

## Verified facts (point‑in‑time; re‑verify if behavior surprises)

Source‑traced 2026‑06‑17 against `hermes-agent` tag **`v2026.6.5`** (SHA
`d6b9cfa3e1f460f5729553ef42b174da28b765c7`) and the vendored guide. `AIAgent` is
volatile — treat these as "verified then," not "true forever." (Facts 7–9 are a
separate, later live-probe dataset — dated and caveated inline, not traced
against this same tag/SHA.)

1. **`enabled_toolsets` semantics** (`model_tools.py` `_compute_tool_definitions`, the `if enabled_toolsets is not None:` branch). **This is load‑bearing for our security gate:**
   - `None` → **enables EVERY toolset** (the `else` branch iterates `get_all_toolsets()`), including `terminal`, `file`, `browser`, `code_execution`, `computer_use`.
   - `[]` (empty list) → **enables NO tools** (`is not None` is True → empty loop).
   - `["web", ...]` → exactly those (after composite expansion + `disabled_toolsets` subtraction + per‑tool `check_fn`).
   - ⇒ Our adapter passes `enabled_toolsets=list(toolset)` **verbatim** — never `… or None`. An empty/omitted toolset (incl. the synthesizer) must be `[]`, not `None`. (`HERMES_KANBAN_TASK` env can append the non‑privileged `kanban` toolset even to `[]`.)
2. **Toolset privilege classification** (`toolsets.py` `TOOLSETS`). **Privileged** (act on the machine / external systems / spawn agents): `terminal`, `file` (write‑capable), `code_execution`, `computer_use`, `browser`, `debugging` (composite = `web`+`file`+`terminal`), `delegation`. **Safe** (read/search/analyze/generate/reason): `web`, `search`, `x_search`, `vision`, `video`, `image_gen`, `video_gen`, `tts`, `moa`, `todo`, `clarify`, `safe`, plus others. Our config gate (`cadre/config.py` `SAFE_TOOLSETS`) is a **fail‑closed allowlist**: anything not safe — privileged, composite, or unknown — needs `allow_privileged_tools: true`.
3. **Timeouts** (`agent_init.py` / `chat_completion_helpers.py`). **No `timeout` kwarg on the constructor or `chat()`.** Instead: a stale‑response detector (~90 s non‑streaming; ~120 s streaming TTFB + ~180 s idle) **plus** an OpenAI‑client timeout (**default 1800 s**) — both **raise into `chat()`**, so a hung provider self‑terminates and surfaces as a catchable exception (our adapter's `except Exception` turns it into a typed failure). Configure on the host via `HERMES_API_TIMEOUT` (env) or `cli-config.yaml` `providers.<id>.request_timeout_seconds` / `models.<model>.timeout_seconds`. Distinct from `max_iterations` (agent‑loop bound, **default 90**).
4. **Provider / model resolution** (vendored guide). `AIAgent(provider=…, api_key omitted)` inherits OAuth/configured providers from Hermes auth — no per‑call key needed. **OpenRouter** uses the full `vendor/model` slug; **OAuth providers** (`xai`, `openai-codex`, `nous`) use `provider=` + a **bare** model id. The library does **not** auto‑read a default provider — set it explicitly per specialist.
5. **Stateless / parallel** (vendored guide, "Thread safety"). Use `skip_memory=True` + `skip_context_files=True` for stateless runs; **create one `AIAgent` per thread/task, never share across threads.** We use `quiet_mode=True` too. (U1 spike empirically confirms provider inheritance and records the exact exception type on a deliberate failure, on the real host.)
6. **`quiet_mode=True` does NOT silence the per-call spinner, but it is stderr-only and TTY-gated** (dogfood 2026-06-23/06-24, real host — CONFIRMED). Despite `quiet_mode=True`, AIAgent's "thinking" spinner (`◞ (｡•́︿•̀｡) pondering…`, `(⊙_⊙) musing… (Ns)`, `٩(๑❛ᴗ❛๑)۶ ruminating…`) prints during a live fleet run **in an interactive terminal**, interleaved with our `[cadre]` stderr breadcrumbs — so `python-library.md`'s "suppresses CLI spinners, progress indicators" is **not absolute**. A stream-separated re-run (`1>report 2>progress`) settled the two open questions: the spinner is **stderr-only and TTY-gated** — absent from BOTH files when the streams are piped (`grep -cP '\(\d+\.\d+s\)'` → `0` on report **and** progress; `grep -cF '[cadre]' report` → `0`). Net: a **non-issue for the agent/subprocess consumer** (who pipes stderr, so no spinner) and **R9 holds** (the stdout report is spinner-free by construction); cosmetic-only on a human TTY, so no code fix is needed. The spinner's signature is the `(N.Ns)` ticker — `[cadre]` lines print elapsed *without* parens, so `\(\d+\.\d+s\)` matches the spinner only.
7. **Palette auto-discovery reads `hermes_cli.inventory` in-process** (observed live on a provisioned Hermes host, 2026-07-06 — this is a **live runtime probe**, NOT source-traced against a pinned tag/SHA like facts 1–6 above: `hermes_cli` is an internal package the vendored guide and `llms.txt` don't cover, so treat it as more volatile than the rest). Access: `from hermes_cli.inventory import build_models_payload, load_picker_context`; `ctx = load_picker_context()`; `payload = build_models_payload(ctx, probe_custom_providers=False, picker_hints=True)` — headless (no interactive picker, no running gateway/JSON-RPC dependency) and **zero spend** (no model call). Full signature observed: `build_models_payload(ctx: ConfigContext, *, include_unconfigured: bool = False, picker_hints: bool = False, canonical_order: bool = False, pricing: bool = False, capabilities: bool = False, force_fresh_nous_tier: bool = False, refresh: bool = False, probe_custom_providers: bool = True, max_models: int | None = None) -> dict`. Chosen over a subprocess CLI call because Hermes exposes no stable headless list-providers command (the CLI's own provider picker is interactive; the dashboard's JSON-RPC surface needs a running gateway) — and cadre already runs inside the Hermes venv (the same interpreter that has `run_agent`), so this import is the same coupling class as that existing one, not a new one. (`cadre/discover.py`.)
8. **Inventory payload shape** (same probe as #7). Top-level keys: `model`, `provider` (the host's *current* selection), and `providers` (a list of rows). A normal row's keys: `authenticated, is_current, is_user_defined, models, name, slug, source, total_models` — **no `auth_type` key at all**; only Hermes's own aggregator row (`name: "Mixture of Agents"`) carries `auth_type: "virtual"` plus a `warning` string, so code reading `auth_type` must `.get()` it, never assume it's present. `slug` is the provider string cadre composes `(provider, model)` pairs from — observed on the probe host: `openai-codex`, `openrouter`, `copilot`, `anthropic`, `xai-oauth`, `minimax-oauth`, plus the aggregator's `moa`; `name` is display-only, never a lane identifier. `source` observed values: `hermes`, `built-in`, `virtual`. `models` entries are bare strings on the probe host (an OpenRouter id contains a `/`, e.g. `deepseek/deepseek-v4-pro`), but the surface can also emit `{"id": ...}` dict entries — cadre's discovery normalizes both shapes and raises rather than silently dropping anything it doesn't recognize.
9. **Custom/BYO providers — source-verified, not live-confirmed** (U9 dogfood 2026-07-07; upgraded from "confirmed-pending"). Every row carries `is_user_defined` (`false` for all 7 rows on the dogfood host — none configured there, so still no empirical exercise). Read directly from the host's installed `hermes_cli/inventory.py` (not just the docstring): `list_authenticated_providers` **enumerates user-defined/custom providers as payload rows** — `probe_custom_providers=False` (the flag cadre passes) only skips their live `/models` re-fetch, and the row still carries its configured models; the payload-level aggregator dedup even special-cases user-defined rows so their model lists survive. Since `cadre/discover.py` filters only unauthenticated rows and `auth_type: "virtual"`, a configured custom provider **would appear in discovered candidates** with its configured model list. Caveat unchanged: no host with a custom provider has exercised this end to end yet — the first operator with one should confirm and re-date this fact.
10. **AIAgent has a SECOND failure shape: error-string-as-response-text** (observed live 2026-07-07, U9 #61 dogfood on a provisioned host; filed as cadre #76). The known shape — provider unusable at resolution time (e.g. no API key found for the provider) — returns **`None`** from the call, which our adapter and `verify-palette` handle (a `minimax-oauth` lane exercised it honestly in the same run). But an **SDK-level auth/client failure inside the call** (an `anthropic` direct row whose key never reached the SDK: "Could not resolve authentication method…", non-retryable, aborts after attempt 1) came back as a **normal non-empty response string containing the quoted error message**. Consequences for integrators: (a) a None-check alone does NOT detect all AIAgent failures — the error text false-verified two palette pairs and rendered as an `[ok]` lane with exit 0; (b) on this path AIAgent prints its error banners (the `🧾` request-dump notice + `⚠️`/`❌` lines) to **stdout even when piped** — unlike the fact-6 spinner (stderr-only, TTY-gated) — so a lane hitting it pollutes an otherwise cadre-clean stdout report. Detection fix, if any, belongs at the adapter reading AIAgent's *structured* result, never content-sniffing the text (a model legitimately quoting an error must not be misclassified).
